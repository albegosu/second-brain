# Product definition

## What it is

second-brain turns the posts you share from your phone or laptop into a personal
knowledge base that a coding agent can use. You share a video, image or page from
X, Instagram, LinkedIn or any site; a model looks at it, works out the interface
pattern, feature or tool it shows, and merges it into a Markdown wiki in your own
repository. When you later ask Claude to build something, it checks that wiki
first.

## Who it's for

People who build products and collect references as they scroll: designers and
developers who save UI demos, feature ideas and tools, and who want those saves to
shape what their AI assistant builds instead of rotting in a bookmarks folder.

## The loop

1. **Share** a link from any app with the Shortcut. No app to install, no account.
2. **Queue.** A cloud inbox accepts it instantly, even with every computer off.
3. **Understand.** A worker downloads the media, samples frames across the video,
   measures the palette and asks a vision model for patterns, style and a topic.
4. **File.** A source note keeps what was extracted verbatim; the topic page
   absorbs what's new, citing the source; the index is rebuilt; the change is
   committed to a private wiki repository, apart from the engine.
5. **Notify** the phone with where it was filed.
6. **Use.** The `second-brain` skill reads the index, opens only the relevant
   topics and cites the sources while Claude designs or builds.

## What makes it different

In a survey of comparable products in September 2026 (save-anything apps,
short-video organizers, AI bookmark managers, design reference libraries and
agent memory tools), none of them did the following. This is the product.

1. **It understands interface video visually.** Frames are sampled across the
   whole video and a vision model describes each interaction as a trigger,
   numbered behavior steps, animated properties and easing. Short-video
   organizers index what is *said* (captions, transcripts); save-anything apps
   tag what an image *contains*. None of them capture how an interface *moves*.
2. **It measures instead of guessing.** The palette comes from pixels, with
   neutrals and brand accents kept apart. Facets and style traits come from a
   closed vocabulary. Durations and cubic-bezier curves are deliberately left out,
   because still frames can't measure them.
3. **The output is a wiki you own, in git.** Topic pages synthesize several
   captures with inline citations, and every capture keeps a verbatim source note.
   Other products keep your saves in a proprietary library as cards and tags.
4. **It is built to be consumed by a coding agent.** The index, topic pages and
   source notes are laid out for an agent to navigate in one context window, and a
   skill tells it how. The goal is references that change what gets built, not a
   library to reread.
5. **Your own references, not a curated catalog.** Mobbin and Refero give agents
   excellent references chosen by someone else. second-brain gives them what *you*
   found worth keeping, with your notes.
6. **Design, features and tools in one place.** Inspiration tools only keep
   visuals; reading tools only keep text. A UI animation, a product behavior worth
   copying and a library to try all land in the same wiki.
7. **Capture without an app, processing without a computer, at zero cost.** A
   system Shortcut on iOS and macOS, a free Supabase inbox, GitHub Actions and the
   Ollama Cloud free plan. Nothing to install on the phone and nothing that needs
   your laptop to be on.

## Principles

- **Code writes the structure, the model writes the prose.** Frontmatter, source
  lists and the index are generated by code, so a bad model answer can spoil a
  paragraph but never the navigation.
- **Every claim points to a source.** Source notes keep the extraction verbatim;
  topic pages cite them as `[n]`.
- **No invented precision.** No made-up durations, no measured-looking curves, no
  framework names the model can't see.
- **References, not code.** The wiki never stores generated components; code is
  written at build time, in the context of the real project.
- **Personal by default.** Captures may include content fetched with your own
  logged-in sessions. It's for your use, not for redistribution.

## Non-goals

- A public inspiration gallery or a social product.
- A custom browsing UI: GitHub and any Markdown editor already render the wiki.
- Replacing curated reference libraries: they complement your own saves.
- Pixel-perfect reproduction of what was captured.

## Closest alternatives

| Product | Overlap | What it lacks here |
|---|---|---|
| mymind | Save anything with AI tagging; image recognition; API and MCP | Tags instead of a synthesized wiki; no motion analysis; paid |
| Fabric | Saves and transcribes TikToks and Reels; MCP | Understands speech, not the interface on screen |
| ReelRecall, Recollect AI, Squil, Ordo | Organize saved short videos | Transcript search; little or no agent access |
| SaveHere | Share sheet → yt-dlp and JSON-LD → Claude → Supabase | Summaries of captions; no vision, no wiki, no MCP |
| Karakeep | Self-hosted AI bookmarks with OCR, rules and MCP | No video understanding |
| ContextBolt | Bookmarks from X, Reddit and LinkedIn served to Claude Code over MCP | Browser only; no vision |
| Readwise Reader | Reading and highlights with an official MCP | Text only |
| Stele | Captures real web UI as code and tokens, with MCP | Web pages only, not social video |
| Mobbin MCP, Refero | Curated app screens and design systems for agents | Someone else's references, not yours |
| Obsidian Web Clipper | LLM-powered clipping into a Markdown vault | You design and maintain the organization |
| Karpathy's LLM wiki | The same raw sources → compiled wiki → index pattern | A pattern, not a capture pipeline |
